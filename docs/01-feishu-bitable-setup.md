# 第一步：一张表，两个账本

新建飞书多维表格 Base，再建“一体账本”。本版用一张表里的 `账本` 单选区分生意/项目和生活，不是两张独立表。

| 字段 | 类型 | 设置 |
| --- | --- | --- |
| 事件 | 文本，主字段 | 具体事件或摘要 |
| 时间 | 日期 | `yyyy/MM/dd HH:mm`；开启新记录自动填入创建时间 |
| 收支 | 数字 | `0.00`，收入为正、支出为负 |
| 账本 | 单选 | `生意`、`生活` |
| 分类 | **单选** | 参见配置示例；预留 `生意结余` 给自动任务 |
| 来源 | 文本 | 快捷指令写 `快捷指令`，派生行写 `自动联动` |
| 月份 | 公式 | `TEXT([时间],"YYYY/MM")` |
| 收入 | 公式、数字 0.00 | 见下方 |
| 支出 | 公式、数字 0.00 | 见下方 |

收入公式：

```text
IF(AND([账本]="生活",[分类]="生意结余",[来源]="自动联动"),[收支],IF([收支]>0,[收支],0))
```

支出公式：

```text
IF(AND([账本]="生活",[分类]="生意结余",[来源]="自动联动"),0,IF([收支]<0,ABS([收支]),0))
```

在飞书公式编辑器中选择对应字段引用；不要把 Markdown 反引号粘进去。`生意` 是业务分组键，也适用于项目和副业；可以改菜单显示名称，但不要只改字段选项而不改配套脚本。

## 可选的一键初始化

Node.js 18+：先运行 `node tools/init-bitable.mjs --dry-run` 查看结构。把自己应用的凭证及目标 Base 的 `FEISHU_APP_TOKEN` 设置为环境变量后，运行 `node tools/init-bitable.mjs --apply`。

- 脚本只创建新表与公式；发现同名表就停止，不删除、覆盖或迁移原表。
- 失败时记下日志中的新 `FEISHU_TABLE_ID`，检查半完成表再处理，勿反复建表。
- `--insert-sample` 仅用于空白测试 Base；示例数据明确标为“示例数据”，不是自己的账目。
- Base 地址 `/base/APP_TOKEN` 提供 Base 标识；表格地址 `table=TABLE_ID` 提供表标识。知识库地址请先取得实际 Base 标识，不要把 wiki token 当 app_token。

API 结构以飞书[建表接口](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table/create)与[新增记录接口](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/create)为准。

## 视图与统计

建议添加“生意”“生活”“自动联动”三个筛选视图；原始交易统计排除 `来源=自动联动`。视图筛选不会改变底层数据。仪表盘需在飞书界面自行配置，初始化脚本不创建看板。

可选看板：总收入、总支出、净结余、真实交易笔数、月度收支对比、分类支出占比、月度结余趋势。先明确筛选范围，再对对应字段求和；不要把生意明细和生活中的自动汇总重复相加。

例如：生意收入 1000、成本 200，生活消费 100。原始流水净额是 700；每日任务额外生成生活汇总 +800 后，生活视图也是 700，但整表不加过滤求和会得到 1500。

月结余行规范：`事件=YYYY/MM 生意净结余（自动联动）`，`账本=生活`、`分类=生意结余`、`来源=自动联动`、时间为该月 1 日北京时间中午。不要手工使用这些保留标识。负结余减少生活收入，不能当作新的生活消费。
