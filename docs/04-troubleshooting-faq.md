# 常见问题与报错排查指南 (Troubleshooting & FAQ)

如果在运行初始化脚本或 iPhone 快捷指令时遇到问题，请对照下方排查表逐步解决。

---

## 一、飞书开放平台 API 常见错误码速查

如果你想看快捷指令最后一步返回的具体飞书响应，可以在快捷指令最末尾临时加一个 **【显示结果】** 动作查看最后一步【获取 URL 内容】的输出 JSON：

| 飞书返回 `code` | 错误提示 (`msg`) | 根本原因 | 解决方法 |
| :---: | :--- | :--- | :--- |
| **`0`** | `"success"` | **写入成功！** | 正常入表，无需处理。 |
| **`99991663`** / **`10014`** | `app_secret invalid` / `tenant_access_token invalid` | `App ID` 或 `App Secret` 填错，或包含多余空格/换行符 | 打开快捷指令前两个「文本」框，检查 `cli_` 开头的 `App ID` 和 32 位 `App Secret` 是否完整且无首尾空格。 |
| **`91403`** | `Forbidden` / `no permission` | **未将自建应用添加为多维表格的「可编辑」文档应用**，或应用未开通 `bitable:app` 权限并发布版本 | 1. 打开多维表格网页端右上角 `...` → **「添加文档应用」** → 搜索你的机器人 → 权限设为 **「可编辑」**。<br>2. 确认在飞书开发者后台已创建版本并发布。 |
| **`1254045`** / **`1254002`** | `FieldNameNotFound` | 多维表格里的列名与快捷指令发送的字段名不一致 | 确保多维表格中存在 `事件`（文本）、`收支`（数字）、`标签`（文本）、`分类`（多选/单选）这 4 个基础列，或直接使用 `node tools/init-bitable.mjs` 自动建表。 |
| **`1254060`** | `TextFieldConvFail` / 类型转换错误 | 字段类型选错了（例如把 `收支` 建成了文本列，或者把 `分类` 建成了数字列） | 检查 `收支` 列必须是**数字（Number）**类型，`事件` 和 `标签` 必须是**文本（Text）**类型，`分类` 必须是**多选（Multi-select）**或单选类型。 |

## 二、iPhone 快捷指令端常见问题

### Q1：双击手机背面后，没有识别出金额，直接跳出了手动输入框？
- **原因**：我们的正则 `[0-9]+\.[0-9]{1,3}` 默认匹配带小数点的金额（如 `¥35.50`）。如果当前屏幕是纯整数（如微信红包封面 `100` 元整且无 `.00`），正则匹配数量为 `0`，快捷指令会自动兜底弹出数字键盘让你手输。
- **进阶修改**：如果你希望同时匹配无小数点的整数，可将【匹配文本】动作中的正则改为 `[0-9]+(\.[0-9]{1,3})?`（但注意这样可能会把页面上的时间、电量百分比也识别进候选列表，因此默认只匹配小数最稳）。

### Q2：入表成功后，为什么 `时间` 列是空的，且 `月份` 公式显示空白？
- **原因**：你在飞书网页端手动创建 `时间`（日期类型）列时，忘记勾选 **「新记录自动填入创建时间」**。
- **解决**：在多维表格里双击 `时间` 列的表头 → 打开 **「新记录自动填入创建时间」** 开关 → 点击确定。此后每一笔快捷指令写入的新记录都会自动填上当天日期，`月份` 公式也会立即算出 `YYYY/MM`！

### Q3：我只需要一个账本，不需要区分「日常」和「副业」，怎么设置最省事？
- **方法 1（不改捷径）**：将快捷指令里的 `biz_url` 和 `life_url` 填入**同一个数据表的 API 地址**，所有分支都会写入同一张表，并通过 `标签`/`分类` 列自动区分。
- **方法 2（一键单表初始化）**：运行 `node tools/init-bitable.mjs --mode single`。

### Q4：截屏图片会保存在手机相册里占空间吗？
- **不会**！快捷指令中的【截屏】动作默认只在内存中生成临时图像并传给下一步的【从图像中提取文本】，只要你不额外添加「存储到相簿」动作，截屏用完即焚，绝不会污染你的系统相册。
