# 从旧双表版迁移到 v2

旧版分别维护“副业项目账本 / 日常消费账本”，使用 `标签`、多选 `分类` 和 `渠道`。v2 是一张表，新增 `账本` 和 `来源`，`分类` 为单选。**不是替换快捷指令就能直接兼容。**

已有 v1 用户可以继续保留原表；这次仓库更新不会接触任何人的线上账本。旧代码可在 [v1 历史提交](https://github.com/shimeiyou/feishu-shortcut-ledger/tree/612b31b) 查看。没有自动执行的迁移或删除脚本。

## 建议步骤

1. 导出旧双表原始流水和已有自动结余，保留只读副本。记录旧任务/自动化，暂不改正式数据。
2. 在测试 Base 新建 v2 一体账本，按下面映射导入**原始交易**：

| v1 | v2 |
| --- | --- |
| 副业/项目表的原始记录 | `账本=生意` |
| 日常表的原始记录 | `账本=生活` |
| 事件 | 事件 |
| 有符号收支 | 收支，不重复翻转正负号 |
| 分类数组或标签 | 人工核对后选一个单选分类；不要直接把数组写入字符串字段 |
| 原始时间 | 时间，保留毫秒/时区语义，不全部改成导入当天 |
| 渠道 | 如需保留，另建渠道列或保留在原始导出中；当前快捷指令不写渠道 |
| 来源 | 导入原始交易填 `迁移导入`，不是 `自动联动` |

3. **旧自动汇总行不要和原始交易一起导入。** 它们已汇总了生意明细，重复导入会双算。保留在只读导出中，新版预演根据原始交易重新计算。
4. 按月份核对原始笔数、生意收入/支出/净额、生活原始收入/支出。建立联动后，再核对生活视图可支配净额。跨账本对账排除自动联动行。
5. 使用通用快捷指令接入测试表，完成四个入口和失败路径的真机检查。确认表结构、金额、日期及统计一致后再切换实际入口。
6. 开新云端项目先预演。暂停旧版月结余脚本/快捷指令内联动/本机定时器，再启用新版写入、首次验证及每日任务。不要同时运行两个派生汇总写入器。
7. Sheets 仅按需要重新选装，指向专用备份文件；不要把旧版 Google 表当成反向恢复来源。

有一个已经符合 v2 结构的账本时，可以使用现表：先备份并预演检查，沿用已有标识，不要再次运行初始化工具。泛化版本的目标表检查会拒绝不匹配字段。

迁移期间以保留的原始交易和按月独立核对结果为准；自动行是可以重算的派生记录。保留旧只读备份，出现疑问先停自动任务，不直接批量覆盖账目。
