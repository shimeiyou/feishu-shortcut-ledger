## 一、法律与开源边界：「思想与表达二分法」（Idea–Expression Dichotomy）

根据《中华人民共和国著作权法》、TRIPS 协定第 9 条第 2 款以及国际通行的开源合规准则，著作权法遵循核心的**「思想与表达二分法」**：

1. **不受著作权垄断的「思想、操作方法与通用公式」**：
   - **功能性流程与操作步骤**：例如“在 iPhone 支付成功后双击手机背面 → 自动截屏 → 调用 iOS 原生图文识别（OCR） → 用正则表达式提取带小数点的数字 → 弹出菜单选择分类 → 通过 HTTP 请求写入云端表格”。这属于**操作方法、技术方案或功能性工作流（Method of Operation / Functional Workflow）**，任何个人或商业作品均无权垄断该思路。
   - **通用会计恒等式与电子表格公式**：例如用正数代表收入、负数代表支出，或使用 `IF([收支]>0,[收支],0)`、`IF([收支]<0,ABS([收支]),0)`、`TEXT([时间],"YYYY/MM")`、`收入 - 支出` 等标准表格函数。这些属于客观数学逻辑与平台标准语法，不具备著作权独创性门槛。
   - **官方开放接口（Open API）的调用方式**：调用飞书开放平台公开文档规定的 `POST /open-apis/auth/v3/tenant_access_token/internal` 与 `POST /open-apis/bitable/v1/apps/:app_token/tables/:table_id/records` 属于标准接口对接。

2. **受著作权保护的「具体独创性表达」**：
   - 他人教程文章中的**原文段落、配图与界面截图**；
   - 他人制作的**飞书多维表格在线模板链接或导出文件**；
   - 他人编写并分享的**原始 `.shortcut` 快捷指令二进制/Plist 文件**（含其内部特定的动作 UUID 序列与硬编码配置）。

## 二、本仓库如何做到 100% 洁净室实现（Clean-Room Implementation）

为确保项目在法律合规与社区声誉上无懈可击，本仓库在设计与实现时严格执行了以下 **5 项洁净室原则**：

| 维度 | 常见第三方/旧式做法 | 本开源仓库的洁净室原创实现 |
| :--- | :--- | :--- |
| **1. 多维表格构建方式** | 依赖复制他人的飞书多维表格公开模板链接（`feishu.cn/base/...`） | **零外部模板依赖**：完全从空白多维表格自建，并独创提供零依赖 Node.js 脚本（`tools/init-bitable.mjs`）与 `lark-cli` 脚本（`tools/init-lark-cli.sh`）通过官方 API 一键建表与配置公式列。 |
| **2. 接口与鉴权架构** | 依赖飞书捷径助手（`botbuilder.feishu.cn`）或第三方封装的闭源 Webhook 转发服务 | **直连飞书开放平台官方 REST API (`bitable/v1`)**：使用用户自己在飞书开放平台创建的企业自建应用（`tenant_access_token` + `records` 接口），无任何第三方中转，数据 100% 掌握在用户自己手中。 |
| **3. 账本与字段模型** | 单一消费表，或需要分别向多个字段重复传参 | **「双账本路由 + 单列有符号收支 + 3 公式派生 + 8 看板组件」架构**：快捷指令仅需写入带正负号的 `收支`（正数为收入、负数为支出）与 `事件`/`标签`/`分类`，由多维表格内的 3 个公式列（`收入`、`支出`、`月份`）自动完成拆分与聚合。 |
| **4. 快捷指令文件生成** | 直接修改他人分享的 iCloud 捷径链接并二次分发 | **纯代码从零编译生成（`tools/build-shortcut.py`）**：使用 Python 标准库 `plistlib` 从结构化配置文件 `config/shortcut-config.example.json` 直接生成全新的 XML Plist 与签名捷径，所有动作节点、UUID 与导入提问（`WFWorkflowImportQuestions`）均由脚本原生构建。 |
| **5. 教程文档与配图说明** | 摘抄或改写现有文章段落 | **全篇原创撰写**：从零基础概念、飞书开放平台权限矩阵、接口排错码到 iPhone 辅助功能触发，每一行正文与脚本注释均为原创编写，并以 MIT 协议开源。 |
